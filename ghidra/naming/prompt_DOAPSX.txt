PlayStation game Dead or Alive (Tecmo, 1998, US SLUS-00606; PsyQ SDK, GCC for MIPS R3000). FILE is the decompile of a slice of one program: main exe SLUS_006.06 (0x80010000-0x80094800), MOVIE.EXE (FMV player at 0x80100000), or a code overlay from the PS_DOA.BIN archive (OV00 big overlay and OV02 both at 0x80093420 in the same slot, OV04 at 0x801e8000); overlay calls below 0x80094800 go into the main exe. Research only. Game: 3D fighting game (Tecmo, Team Ninja) ported from the Saturn/Model 2 version: fighters (Kasumi, Ayane, Leifang, Jann Lee, Zack, Tina, Gen Fu, Bayman, Raidou, Ryu Hayabusa, Bass; PSX adds extra fighters/modes vs Saturn), counter/throw/hold system, stages with danger zones, versus/arcade/team battle, ranking/name entry (strings "Ranking", "STAGE1"), memory card, CD audio tracks.
Names already given (biosA0_*, biosB0_*, biosC0_* = BIOS call stubs from public psx-spx tables; stub_/retN_) are trusted. Some blocks carry a "/* decider hint: ... */" line: hw= hardware blocks touched (cdrom 0x1f801800, gpu 0x1f801810/14, mdec, spu 0x1f801c00.., dma 0x1f801080.., timer 0x1f801100.., irq 0x1f801070/74, sio = pad/memory card 0x1f801040..), gte=N = count of GTE (cop2) ops, cop0=N, str= strings. Use them.
SAME GAME LOGIC as the Saturn decomp (SH-2, already hand-named): <SATURN>/hand_00DOA.txt (lines: 0x0600xxxx func <name> hand <comment>). When a PSX function does the same job (same strings, same constants, same call shape, same state-machine role), reuse the Saturn name (grep that file for the topic or constant words, e.g. "throw", "hold", "ranking", "stage", "camera"). Use the same module prefixes. Do not Read the whole file; Grep it.

Task: name functions from the Ghidra decompile. FILE holds a slice. Name EVERY function in FILE whose name is still FUN_xxxxxxxx (skip ones that already have a name).
Evidence: strings, callees, PSX hardware registers, GTE ops (RotTransPers, RotMatrix, MulMatrix, NormalClip, AverageZ), GPU primitive packets (code byte at +7: 0x20 POLY_F3, 0x24 FT3, 0x28 F4, 0x2c FT4, 0x30 G3, 0x34 GT3, 0x38 G4, 0x3c GT4, 0x64 SPRT, 0xe1 draw mode), libcd (CdInit, CdControl, CdRead, CdSync, CdSearchFile, CdIntToPos), libgpu (ResetGraph, PutDrawEnv, PutDispEnv, DrawSync, VSync, LoadImage, ClearImage, GetTPage), libetc (PadInit, VSyncCallback, ResetCallback), libspu/libsnd, libcard/libmcrd, libapi, libc (sprintf, memcpy, rand, strlen). Only use a PsyQ API name when the behaviour clearly matches; otherwise a descriptive name. Fixed point 4096 = 1.0, angles 4096 = 360 degrees.
Style: lowercase module prefix + CamelCase verb, e.g. gpu_AddPolyFT4, cd_ReadSectors, pad_Read, fighter_UpdateState, hit_CheckAttackBox, menu_DrawCursor, math_FixedMul, mem_Copy. PsyQ library functions keep their SDK name. Tiny stubs that only return: stub_<addr>. Data mistaken for code: data_<addr>. When unsure, still give the best descriptive name and start the comment with "provisional".

Output: write lines to OUT (create it with Write; one line per function, no other text):
0x<addr> func <name> hand <comment of 5-20 words: what it does, key callees, registers or strings>
Addresses as 8 lowercase hex digits. Names unique within OUT; append _2, _3 on collisions. Do not put quoted strings longer than 3 words in comments. Read FILE in pieces (offset/limit, about 600 lines at a time) to the end. Reply only with the line count.
Rule: name every function by reading its code yourself. Never generate names with a script or by pattern. Do not create helper files. Start no programs.
